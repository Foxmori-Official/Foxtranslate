# Foxtranslate 更新与参考项目跟踪

这份文档用于更新扩展本身，以及从参考项目中选择适合的改进。

## 日常检查

`docs/upstreams.json` 是六个参考仓库及关注方向的清单。`docs/upstream-baseline.json` 只记录已经由维护者审阅过的完整提交 SHA。

```sh
npm run check:upstreams
```

命令通过 GitHub API 读取默认分支提交、最新正式 Release、许可证标识和从人工基线到当前提交的差异，生成 Markdown 与 JSON。无 Release 的项目仍按提交检查。比较接口不可用或历史被重写时，报告提供提交页供人工核对。网络、权限或限流失败会使命令失败，不会推进审阅基线。

公共 API 未认证时额度有限，本地可用环境变量 `GITHUB_TOKEN` 提供访问令牌。令牌仅用于 GitHub 认证，不写入报告。上游报告属于参考资料，内容中的操作指令需要按本项目需求重新判断。

## GitHub 上的自动提醒

`.github/workflows/upstreams.yml` 在每周一北京时间 09:17、跟踪清单或脚本变更以及手动触发时运行。报告保存为工作流制品，并更新带固定标记的同一条待审阅 Issue。

首次运行没有人工基线，所有参考项目都会出现。审阅后在 JSON 的 `reviewed` 对象内为对应仓库填写以下记录。

```json
{
  "reviewed": {
    "owner/repository": {
      "sha": "上游完整的40位提交SHA",
      "reviewedAt": "2026-11-11",
      "decision": "采用某项修复，其余暂缓；关联本项目PR或Issue"
    }
  }
}
```

示例中的占位值需要替换为报告中的实际仓库和提交。基线表示已经读过哪些变化，具体采用到何处需在 PR 和变更记录中单独说明。脚本不会自动合并上游代码，也不会执行上游脚本。

GitHub 的定时任务受默认分支、Actions 启用状态和平台调度影响。可从 Actions 的 Reference project updates 工作流手动运行，也可在本地执行命令。

## 选择适合的更新

每轮按以下顺序审阅。

1. 先读 Release 的面向用户说明，再打开差异与相关源文件。重点寻找当前缺陷的修复、兼容性调整和已有能力的补充。
2. 在 Issue 记录当前 Foxtranslate 是否已经实现、用户收益、依赖成本、权限变化和需要验证的行为。
3. 阅读涉及文件的许可证与归属。采用代码片段时保留版权及许可信息，在 THIRD_PARTY_NOTICES.md 记录源路径、提交和修改。涉及不同 copyleft 许可时，先确定项目许可如何满足要求。
4. 为每一项变化明确记录“采用”“暂缓”或“不采用”及原因。功能介绍不等于可直接移植，先确认本项目架构和数据模型适合。
5. 每个 PR 聚焦一个可验证行为，增加能复现原问题的测试。引擎以模拟请求验证协议，并用自备服务补充人工检查。
6. 审阅结束后提交人工基线与决定记录。避免把“已经看过”与“已经合入”混为一个状态。

## 本地更新与回归

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run verify:package
npx playwright install chromium
npm run test:browser
```

浏览器集成测试使用隔离配置目录与本地或拦截后的页面。它证明控件、存储、路由、生命周期和协议能协同运行。发布前仍需在真实 Chrome、Edge 和当前 YouTube 页面验收以下流程。

- 初次安装自动打开引导，保存失败时保持可重试状态，完成后不在更新时反复弹出。
- 弹窗、设置、引导、文档、复习和隐私页面的导航始终位于左侧，工作区始终位于右侧。窄屏缩小侧栏，内部字段可换行。
- 中文、英文和德文无控件越界，自定义下拉可用箭头键、Enter 和 Escape 操作。
- 翻译、恢复、切换网页、修改目标语言和站点策略符合界面说明，慢请求不覆盖新状态。
- YouTube 普通视频播放器有 狐狸图标按钮。关闭仍可重新开启，SPA 切视频和播放器替换后只有一个按钮，全屏仍可访问。
- 有字幕轨的视频可显示双语字幕。无字幕轨、请求失败和广告时表现可解释，关闭后恢复原生字幕显示。
- 文档上传、取消、校订和导出能完成，失败片段与成功输出符合提示。生词保存与复习评分能持久化。

## 发布

1. 更新 package.json 和 public/manifest.json 的版本，更新 CHANGELOG.md。版本必须一致，标签格式为 `v0.1.0`。
2. 提交并通过 CI。运行 `npm run zip` 得到 `release/foxtranslate-版本.zip`，包根目录必须直接包含 manifest.json。
3. 创建对应标签并推送。Release 工作流重复检查、构建、验证并计算 SHA-256 校验和，创建草稿 Release。
4. 从草稿下载 ZIP，以全新浏览器配置加载并按上面的清单检查，同时检查从上一版覆盖升级后的配置、生词和快捷键。
5. 在 Release 写明新增、修复、兼容性变化、已知限制和参考的上游提交，验收后发布草稿。商店上传需另行提交审核。
6. 出现回归时修复并发布更高版本，或给出回退安装包。浏览器更新依赖商店签名与版本检查，普通开发者加载的扩展需要手动替换并重新加载。
